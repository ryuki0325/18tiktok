# 01. 概要と前提

## 1. プロダクト定義

| 項目 | 内容 |
|---|---|
| 名称 | Glow（仮称） |
| 一言 | 大人のための、特別なショート動画プラットフォーム |
| 対象 | 18歳以上。日本を主な対象としつつ、**海外からのアクセスも許可する**（国・地域ごとの規制に対応するため、地域ポリシー層を置く。03 `geo_policies`） |
| 形態 | Webアプリ（PWA対応）。モバイル幅360〜430pxを最優先し、PCでは中央にスマホ幅のカラムを表示する |
| 収益（当面） | なし。無料で利用者を増やす。将来は広告枠とサブスクを追加できるよう、拡張点だけ用意しておく |
| 収益（投稿者） | 投稿者は運営が許可した提携先のアフィリエイトURLを動画に付け、視聴者を外部サイトへ案内する。決済と報酬の計算は提携先が行う |
| 差別化 | ①大人向けの洗練されたUI ②**利用者が自分でアプリのデザインテーマを変えられる**（同じUXのまま、見た目を自由に変えられる） ③広告っぽさが少ない |

> **ネイティブアプリにしない理由**：App StoreとGoogle Playはどちらも成人向けコンテンツのアプリを審査で認めていません。このため配信はWeb（PWA）だけにします。UIはiOSのHuman Interface Guidelinesの寸法感覚に合わせ、ホーム画面に追加すればネイティブアプリに近い操作感になるようにします。

## 2. スコープ

### 作るもの（全フェーズ）
- 閲覧者：年齢確認ゲート、初回のタグ選択、縦スワイプのフィード（おすすめ/人気/フォロー中）、検索、タグ一覧、投稿者ページ、お気に入り、フォロー、**コメント**、通報、外部遷移の確認画面、ランキング、新人枠、特集枠、**デザインテーマ設定**
- 投稿者：申請、本人確認、進捗表示、動画投稿（再開できるアップロード）、投稿一覧、ダッシュボード、通知
- 運営：ダッシュボード、動画審査キュー、通報キュー（SLA付き）、投稿者管理、制裁、許可ドメイン管理、URL審査、削除請求の管理、特集枠、各種閾値の設定、運営者表示の設定、監査ログ、ロール管理
- 法務：利用規約、プライバシーポリシー、投稿ガイドライン、削除・権利侵害申告ポリシー、運営者情報、特商法表記（将来用）の雛形と申告フォーム

### 作らないもの（要件に明記されているもの）
- 運営者を特定されないための偽装機能
- 審査や通報をすり抜けるための機能
- 多段階の紹介報酬（マルチ型）
- 自サイトでの決済や報酬の自動分配
- 投稿者以外が動画をダウンロードできる機能

## 3. 設計の原則

1. **安全側に倒す**：迷ったら「表示しない」「公開しない」を初期値にする（動画は審査が通るまで非公開、URLは許可されるまで表示しない、通報されたら先に非公開にする）。
2. **サーバーで判定する**：年齢ゲート、公開状態、権限はすべてサーバー側（APIとDBのRLS）で判定する。フロントの判定は見た目のためだけに使う。
3. **ログは追記だけ**：同意記録、監査ログ、通報の対応履歴は更新・削除ができない追記型のテーブルにし、ハッシュチェーンで改ざんを検出できるようにする。
4. **個人情報は必要最小限**：IPアドレスは原則ハッシュ化し、生のIPを残す場合は保存期間をつける。本人確認書類は別のバケットに暗号化して保存し、保存期間が過ぎたら自動で削除する。
5. **差し替えられる設計**：動画の保存先、本人確認、違法コンテンツの自動検知、重複検知、メール送信はインターフェース（Provider）を挟み、後から事業者を替えられるようにする。
6. **値は設定で変える**：閾値（審査が必要な本数、自動非公開になる通報数、人気スコアの式、新人枠の日数、保存期間など）はコードに直書きせず、`site_settings` で管理画面から変えられるようにする。

# 02. 技術選定・動画保存先の比較

> **注意（必ずお読みください）**
> 料金と「成人向けコンテンツを置けるか」は、公開情報をもとにした**初期評価**です。2026年10月時点の各社の規約原文は、まだ確認できていません。
> 成人向けの扱いは、規約の改定やアカウント審査によって予告なく変わることがあります。**契約する前に、①規約（AUP）の原文 ②営業窓口からの書面回答 ③見積もりの3点を必ず確認してください。** この確認作業はフェーズ2の最初のタスクにしています。

---

## 1. 選び方の基準（優先順）

1. **規約上、合法な成人向けコンテンツが置けること**（後でアカウントが止められると事業が止まるため、最優先）
2. 権限を分けやすく、個人情報を安全に守れること（RLS、KMS暗号化、監査ログ）
3. 日本からの速度（東京または大阪にリージョンやPoPがあるか）
4. 運用の手間（小さなチームで回せるか）
5. 料金
6. 他社に乗り換えやすいこと（Provider層を挟むので、どれを選んでも乗り換えられる設計にする）

## 2. アプリ本体の技術構成

| 層 | 推奨 | 他の候補 | 推奨する理由 |
|---|---|---|---|
| フレームワーク | **Next.js（App Router）+ TypeScript** | Remix / SvelteKit | 指定どおり。SSRとミドルウェアを使い、年齢ゲートをサーバー側で強制できる |
| スタイル | **Tailwind CSS v4 + CSS変数（デザイントークン）** | CSS Modules | テーマの切り替えはCSS変数の差し替えだけで済む（07を参照）。Tailwind v4の `@theme` はCSS変数を直接参照できる |
| DB | **PostgreSQL 16+** | — | 指定どおり。RLS、追記専用トリガー、全文検索（pg_trgm）が使える |
| DBアクセス | **Drizzle ORM** + マイグレーションをSQLで管理 | Prisma | SQLに近く、RLSの `SET LOCAL` やトリガーを扱いやすい。生成されるSQLも読みやすい |
| 認証 | **Better Auth**（メール+パスワード、メール確認、TOTPによる2段階認証、レート制限） | Auth.js / 自作 | 2段階認証とセッション管理が標準で入っている。データは自分のDBに置け、外部のIDaaSに個人情報を渡さずに済む |
| 入力検証 | Zod | Valibot | APIとフォームで同じスキーマを使い回せる |

| レート制限 | Postgres（スライディングウィンドウ）→ 負荷が増えたらRedis/Upstash | — | 最初は構成を増やさない。インターフェースを分けておき、後で差し替える |

| エラー監視 | Sentry（個人情報はマスキング） | — | — |
| 秘密情報 | `.env`（ローカル）、本番はホスティング先のSecret Manager | — | リポジトリには `.env.example` だけを置く |

### 2.1 ホスティング・DBの組み合わせ（3案）

| 案 | アプリ | DB | 本人確認書類 | 良い点 | 気になる点 |
|---|---|---|---|---|---|
| **A（推奨）AWS東京でまとめる** | App Runner または ECS Fargate | RDS for PostgreSQL | S3（SSE-KMS、専用バケット、専用KMSキー） | 1社にまとまり、権限（IAM）と鍵の管理（KMS）が強い。東京リージョン。AWSの利用規約は違法なコンテンツを禁止しているが、合法な成人向けを一律には禁止していないと理解している（**要確認**） | 初期設定の手間が多い。料金が分かりにくい |
| B 開発を速く進める | Vercel | Neon / Supabase | S3 または R2 | 立ち上げが最も速い | **成人向けサイトのホスティングについて、各社の規約は未確認（要確認）**。止められた場合の影響が大きい |
| C 国内事業者 | さくらのクラウド等のVPS / コンテナ | 自前のPostgreSQL | 国内のオブジェクトストレージ | データが国内に置かれ、規約も日本語 | 運用の手間が最も大きい。成人向けの扱いは**要確認** |

**推奨は案Aです**。動画本体は2.2の配信サービスに置き、アプリ側のサーバーには置きません。こうすると、アプリのホスティング先には成人向けの映像データが乗りません（ただしサムネイルなどのURLやタイトルは乗ります）。

## 3. 動画保存・配信サービスの比較

求める機能：アップロードを途中から再開できる（tus）、縦動画を複数の画質に変換する（HLS）、サムネイルの自動生成、**署名付き・期限付きの再生URL**、ダウンロード防止、Webhook、日本向けのCDN。

| 項目 | **Cloudflare Stream** | **Bunny Stream** | **AWS自前構成**（S3 + MediaConvert + CloudFront） | Mux | 国内VPS + 自前の変換 |
|---|---|---|---|---|---|
| 成人向けの可否（初期評価） | 規約は違法コンテンツ（CSAM等）の禁止が中心で、合法な成人向けを明示的に禁止する条文は見当たらない → **書面での確認が必須** | 成人向けを扱う顧客が多いと言われている → **要確認** | 違法コンテンツは禁止。合法な成人向けは一律禁止ではないと理解 → **要確認** | 成人向けには**否定的な可能性が高い** → 候補から外す前提 | 事業者による |
| 再開できるアップロード | ◎ tus対応 | ◎ tus対応 | ○ S3マルチパート（自前で実装） | ◎ | △ 自前で実装 |
| 変換（HLS・複数画質） | ◎ 自動 | ◎ 自動 | ○ MediaConvertの設定が必要 | ◎ | △ ffmpegの運用が必要 |
| 署名付きURL | ◎ 署名付きトークン | ◎ トークン認証 | ◎ CloudFrontの署名付きURL/Cookie | ◎ | 自前で実装 |
| ダウンロード防止 | ○ 標準でダウンロード無効、署名で制御 | ○ | ○ | ○ | 自前で実装 |
| 日本からの速度 | ◎ 東京・大阪などにPoP | ○〜◎ 東京にPoP | ◎ 東京・大阪 | ○ | ◎（国内） |
| 料金の目安（**未検証の概算**） | 保存：1,000分あたり約$5/月、配信：1,000分あたり約$1 | 保存はGB単価、配信はGB単価で、アジア向けは標準ネットワークだと高め。変換は無料と言われている | S3：約$0.025/GB/月、CloudFront日本：約$0.11/GB〜、変換は分単位で課金 | 分単位（エンコード・保存・配信） | サーバー代と回線代 |
| 料金の性質 | **「分」課金で予測しやすい** | 「GB」課金で、短尺なら安くなりやすい | 「GB」課金で、配信量が増えると高くなる | 分単位 | 固定費が中心 |
| 運用の手間 | 小 | 小 | 中〜大 | 小 | 大 |
| 総合評価 | **第1候補** | **第1候補（並列）** | 第2候補（規約面では最も安心できる可能性） | 除外予定 | 将来の選択肢 |

### 推奨
1. **Cloudflare Stream と Bunny Stream の2社に、同時に書面で問い合わせます**（「日本向け・18歳以上限定・本人確認済みの投稿者による合法な成人向けショート動画（日本の法令に沿った修整済み）を配信してよいか」）。
2. 可の回答が得られた方を採用します。両方とも可なら、**月の想定配信量で試算して安い方**にします。ショート動画（15〜60秒）なら、Cloudflareの分課金の方が予測しやすいです。
3. 両方とも不可なら、**AWS自前構成**に切り替えます（`VideoStorageProvider` の実装を替えるだけで済む設計にしています）。

### 3.1 概算シミュレーション（参考、**単価は要再確認**）
前提：平均の長さ30秒、1日の再生10万回、1再生あたり平均20秒視聴、保存5,000本（合計2,500分）

| | 保存 | 配信（月） | 月額の目安 |
|---|---|---|---|
| Cloudflare Stream | 2,500分 → 約$12.5 | 10万×30日×20秒 = 100万分 → 約$1,000 | **約$1,000/月** |
| AWS（720p平均1.5Mbps想定） | 小さい | 約3.75MB/再生 × 300万再生 ≒ 11TB → 約$1,100〜 | **約$1,100〜/月** |

→ 利用者が増えるまでは、どの案も月数万円以内に収まる見込みです。正式な比較はフェーズ2の見積もりで行います。

## 4. 本人確認（KYC）の方式

| 方式 | 内容 | 良い点 | 気になる点 |
|---|---|---|---|
| **① 手動アップロード（要件どおり）** | 身分証の画像と自撮りをアップロードし、運営が目視で確認する | 費用がかからない。要件どおり | 偽造を見抜けない。運営の作業が増える。書類を自社で保管するリスクを負う |
| ② eKYC事業者に委託 | TRUSTDOCK、Liquid eKYC など（国内事業者） | 偽造の判定と生体の確認ができる。書類の保管を事業者に任せられることがある | 1件あたり数百円程度（**要見積**）。成人向けサービスでも契約できるかは**要確認** |

→ 設計は `IdentityVerificationProvider` インターフェースを挟み、**最初は①、後から②に切り替えられる**ようにします。どちらにするかは「09 質問リスト」のQ2-1で決めていただきます。

## 5. 非同期ジョブ一覧（pg-boss）

| ジョブ | 実行タイミング | 内容 |
|---|---|---|
| `video.ingest` | 配信サービスからWebhookを受けたとき | 変換完了を反映、尺と解像度を保存、`ContentScanProvider` と `DuplicateDetector` を呼ぶ |
| `video.thumbnail` | 変換が完了したとき | サムネイルを確定（配信サービスの機能を使う） |
| `links.healthcheck` | 毎日（設定で変更可） | 有効なアウトバウンドリンクにHEAD/GETを送り、状態とリダイレクト先のドメインを記録。許可リスト外に飛ばされる場合は自動で無効化 |
| `links.domain-revoked` | 許可ドメインを削除したとき | 該当するリンクを一括で無効化（F-5） |
| `rankings.refresh` | 1時間ごと | 人気スコア、週間・月間ランキング、新人枠を再計算 |
| `retention.purge` | 毎日 | 保存期間が過ぎた本人確認書類、生IP、閲覧イベントの詳細を削除（削除したこと自体は監査ログに残す） |
| `reports.sla-watch` | 5分ごと | 期限が近い通報、期限を過ぎた通報を管理画面に通知 |
| `fraud.scan` | 1時間ごと | 自作自演の疑い（同じ端末からの異常な再生やクリック）を検出し、`fraud_flags` に登録 |
| `audit.verify-chain` | 毎日 | 追記型ログのハッシュチェーンを検証し、途切れていたら警告 |

## 6. 差し替えられるインターフェース（Provider）

```ts
interface VideoStorageProvider {   // Cloudflare / Bunny / AWS
  createUpload(meta): Promise<{ uploadUrl: string; providerVideoId: string }>;   // tus
  getPlaybackUrl(providerVideoId, opts: { expiresInSec: number; viewerKey: string }): Promise<string>; // 署名付き
  getThumbnailUrl(providerVideoId, opts): Promise<string>;
  delete(providerVideoId): Promise<void>;
  verifyWebhook(req): Promise<WebhookEvent>;
}
interface IdentityVerificationProvider { start(...); getResult(...); purge(...) }  // 手動 / eKYC
interface ContentScanProvider { scan(videoId): Promise<ScanResult> }          // 今はダミーで常に"needs_human_review"を返す
interface DuplicateDetector { fingerprint(videoId); findSimilar(fp): Promise<Match[]> }  // まずSHA-256＋サムネイルのpHash
interface MailProvider { send(...) }
interface RateLimiter { hit(key, limit, windowSec): Promise<boolean> }
```
